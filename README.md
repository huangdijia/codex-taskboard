# Codex TaskBoard

Codex TaskBoard 用看板整理本地 Codex 聊天。
用户可以按项目查找聊天。
用户可以打开聊天检查结果。
用户检查结果后，可以在看板中验收聊天。

## 术语

| 术语 | 含义 |
| --- | --- |
| 聊天 | Codex 中的一段对话。 |
| 卡片 | 看板中代表一段聊天的条目。 |
| 验收 | 用户检查结果后，将卡片标记为 `Done`。 |
| 重新打开 | 用户将卡片从 `Done` 改为 `Review`。 |

## 主要功能

- 按项目查看聊天。
- 按项目名称或路径搜索项目。
- 按聊天标题搜索聊天。
- 点击聊天标题，打开原聊天。
- 拖动卡片，验收或重新打开聊天。
- 切换明暗主题。

## 看板状态

| 界面状态 | 含义 |
| --- | --- |
| `InProgress · 进行中` | 看板观察到聊天有新的执行进展。 |
| `Review · 待验收` | 本轮执行结束，或聊天状态待用户确认。 |
| `Done · 已完成` | 用户检查结果，并在看板中验收聊天。 |

看板根据本地聊天记录推断状态。
看板状态更新有延迟。
必须确认执行进度时，打开原聊天。

验收只改变看板中的记录。
验收不改变原聊天内容。
验收不改变原聊天的归档状态。
用户发送新消息后，看板撤销该聊天的验收标记。

## 安装

安装环境必须满足以下条件：

- 使用 Codex 桌面客户端。
- 使用 Node.js 26 或更新版本。

复制以下 prompt，发送给 Codex：

```text
请安装 Codex TaskBoard 插件。
仓库地址：https://github.com/huangdijia/codex-taskboard

1. 查找本地已有仓库。
本地没有仓库时，克隆仓库到合适的工作目录。
必须保留已有未提交改动。
2. 检查安装环境。
3. 使用仓库脚本构建插件。
4. 使用仓库脚本测试插件。
5. 使用仓库的插件配置安装插件。
6. 从 Codex 侧栏打开看板。
7. 检查项目切换。
8. 检查聊天搜索。
9. 检查三列显示。

聊天验收由我手动操作。
请报告安装结果和验证结果。
必须标明未验证的检查。
必须说明重载或重启步骤。
```

## 卸载

复制以下 prompt，发送给 Codex：

```text
请卸载 Codex TaskBoard 插件（codex-taskboard）。

1. 检查插件安装状态。
插件不在已安装列表中时，报告检查结果。
2. 使用 Codex 提供的卸载方式移除插件。
3. 移除仅供该插件使用的安装来源。
4. 检查已安装列表。

必须保留以下内容：
- Codex 聊天。
- 项目文件。
- 本地仓库。
- 看板验收记录。

请报告卸载结果和验证结果。
必须标明未验证的检查。
必须说明重载或重启步骤。
```

## 日常使用

1. 从 Codex 侧栏打开「Codex TaskBoard」。
2. 选择项目。
3. 点击聊天标题。
4. 检查聊天结果。
5. 将卡片从 `Review` 拖到 `Done`。

必须继续执行时，将卡片从 `Done` 拖回 `Review`。

卡片取得键盘焦点后，可以使用以下快捷键：

| 快捷键 | 动作 |
| --- | --- |
| `Alt+→` | 验收 `Review` 卡片。 |
| `Alt+←` | 重新打开 `Done` 卡片。 |

用户不得手动移动 `InProgress` 卡片。
看板提示数据过期时，必须先刷新看板。

看板默认隐藏以下聊天：

- 归档聊天。
- 子 Agent 聊天。
- 自动化聊天。

窗口较窄时，可以横向滚动查看三列。
看板默认跟随 Codex 的主题。
手动切换主题只影响当前看板页面。
重新打开看板后，主题恢复为跟随 Codex。

## 常见问题

| 现象 | 要做 |
| --- | --- |
| 安装后找不到看板，或看板无法打开。 | 重载客户端的插件配置。问题持续时，重启 Codex。 |
| 首次加载较慢。 | 等待看板读取聊天。界面会显示读取提示。 |
| 看板提示读取失败或数据过期。 | 刷新看板。数据恢复后，再验收聊天。 |

## 开发

开发者必须使用 Node.js 26 或更新版本。

1. 安装依赖。

   ```sh
   npm ci
   ```

2. 构建插件。

   ```sh
   npm run build
   ```

3. 执行检查。

   ```sh
   npm run check
   ```

`npm run build` 将构建文件写入 `plugins/codex-taskboard/dist/`。
`npm run check` 执行构建和自动化测试。
Agent 协作规则见 [AGENTS.md](AGENTS.md)。
